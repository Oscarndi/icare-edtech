Interactive financial laboratory

Explore explicit assumptions without changing the official financial model. Calculations remain server-authoritative.

How to use FinRoom

1. Set the scenario. Choose the learner count, device arrangement, home continuity, operating-cost structure and time horizon you want to examine. These inputs create an ephemeral simulation and never rewrite the protected reference model.
2. Read the current snapshot. Use the snapshot to understand the financial position for one explicit learner count under the selected assumptions.
3. Explore the trajectory. Use the horizon and growth controls to examine how the same scenario evolves month by month. A trajectory is a modeled scenario, not a forecast or promise of future performance.
4. Compare or test break-even. Sensitivity compares an explicit variant with the reference configuration. The break-even graph answers a different question: how many active learners are required for monthly contribution to cover modeled operating costs.
Scenario assumptions
Progressive operating-cost plan Use Progressive when operating costs are expected to change over time instead of remaining fixed. Start from Current or Expanded, then add explicit cost or hiring events. FinRoom sends the plan to the protected server; the browser does not calculate operating costs or break-even.

How Progressive events work

  • Start month. An event becomes active in its start month and remains active in later months of the selected horizon.
  • Cost change. Adds the entered monthly amount to operating costs from the selected start month onward. A negative value may represent an explicit modeled cost reduction.
  • Hiring. Defines a positive headcount increase and a monthly unit cost. The protected server resolves the resulting monthly hiring cost.
  • Evidence status. Achieved, Current assumption, To validate and Deferred describe the evidence or validation state of the event. They do not automatically include or exclude the event: every event in the submitted Progressive plan is simulated from its start month.
  • Event ID. A short unique name used to identify the event in the resolved server context and active-event list.

FIELD → MODEL

From assumptions to field evidence

TO VALIDATE

ICARE's financial model is designed to evolve from observed evidence. Field observations may support a proposed revision, but they never update or approve the official model automatically.

1. What does the result mean?

Read the modeled revenue, contribution, operating gap, CAPEX and break-even measures in the context of the explicit scenario assumptions.

2. What drives it?

Active learners, device mode, home continuity, conversion, cost structure, growth assumptions and time horizon can change the modeled outcome.

3. What is excluded?

A modeled contribution is not profit. Costs still marked TO VALIDATE or DEFERRED remain outside a complete economic conclusion until evidence is available.

4. What evidence is needed?

Pilot observations should document the metric, observed value, sample size, observation period, recording date and source before an assumption revision is reviewed.

1

Current assumption

CURRENT ASSUMPTION

A working input used by the model while its evidence base is still being strengthened.

2

Field observation

ACHIEVED

Record what was actually observed, with sample size, period, date and source. Evidence is not approval.

3

Proposed revision

TO VALIDATE

Evidence may justify proposing a different value or maturity status. The proposal is not yet adopted.

4

Human review

TO VALIDATE

The evidence, interpretation and proposed revision must be reviewed explicitly before any official change.

5

Explicit adoption

DEFERRED

Adoption into the official model is a separate governed action. This browser lab neither persists nor performs it.
